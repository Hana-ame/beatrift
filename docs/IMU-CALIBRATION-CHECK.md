# 手机真实姿态自检指南

在 `/test/` 测试台上用**真实手机**逐条验证。目的：区分"算法 bug"（应修复）与"欧拉角万向锁/±180 互换"（表示差异，需用四元数判断正确性）。

## 约定

- 手机坐标系：x=屏幕右，y=屏幕顶，z=垂直屏幕向外。
- 世界系：X=东，Y=北，Z=天。
- 角：先 α（绕 z），再 β（绕新 x），再 γ（绕新 y）。W3C 内旋 Tait-Bryan。
- PC 端四路解：`device`(系统解)、`fuse`(Mahony)、`gyro`(纯陀螺)、`accel`(仅重力)。

## 判定标准（最重要）

**用 3D 长方体/屏幕法线方向判断正确性，别只看欧拉角数值。** 欧拉角在竖立（β=±90）和水平（β 或 γ 过 ±90/±180）时必然出现 ±180 跳变、αγ 互换——只要长方体朝向没反，就是对的。

预期各姿态下**屏幕法线**（世界系，显示在表里的 center 共球方向）：
- 平放屏上：法线朝天 `(0,0,+1)`
- 平放屏下：法线朝地 `(0,0,-1)`
- 竖立屏朝脸：法线朝你 `(0,-1,0)`（朝北拿）
- 无翻转：用 `accel` 解平放屏上应得 γ=0，屏下 γ=±180

## 步骤

### 1. 平放屏上（基准）
- 手机屏幕向上水平放桌面，顶边朝北。
- 期望 手机端：`β≈0，γ≈0，α≈0`；`accel` 与 `fuse` 都 β0 γ0，法线朝天。
- 若 γ 读成 180 → **屏上/屏下颠倒 bug（需修复）**。

### 2. 平放屏下
- 翻面屏幕朝下。
- 期望 法线朝地，γ≈±180，β≈0。
- 若 γ 读成 0（法线朝天）→ 同上 bug。

### 3. 缓慢翻转（复现你描述的问题）
- 平放屏上 → 缓慢绕左侧边（横的 axis）翻 180° 到屏下。
- 观察：何时"卡一下"、何时翻转。记录卡住瞬间的 β/γ 与 屏上/屏下的 α。
- 期望：一路平滑；若在中间出现瞬间 180° 翻转后接续反向，是 γ 过 ±180 回绕，正常。

### 4. 竖立（万向锁区，别把这里当 bug）
- 手机竖立正对自己（portrait）。
- 期望 法线朝向 `(0,-1,0)`，β=90。
- 横过来（landscape）：β=90 时 α 与 γ 会互相顶上，γ 从 +90↔−90 跳，α 补 180°，属 W3C 万向锁，**不是 bug**（只要长方体没反）。

### 5. 原地转 α（绕竖直轴）
- 手机竖立正对北，绕自身竖直轴慢慢转。
- 期望 α 变、β≈90 不变。若 β 也大幅跳、块翻转 → 转序 bug。

### 6. 逆时针 vs 顺时针 对照
- 再一次做第 3 步，但反向（屏下→屏上）。
- 期望结果对称。若两个方向 +反不同 → 符号有中国即问题。

## 上报格式

按上面，报告每个步骤：
```
步骤N: 实际 α/β/γ 或 法线如何 + 长方体朝向 (正/反) -> (正常/翻转/卡住)
```

这样能区分：算法 bug（屏上/屏下颠倒，需修）、万向锁正常现象、或符号问题。
